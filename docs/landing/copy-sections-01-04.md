## Раздел 02 · MAE / MFE

### Eyebrow

**Recommended:** `Раздел 02 — MAE / MFE` *(keep — em-dash на месте)*

### H2

> MAE и MFE — из минутных свечей биржи.

Rationale: H2 отвечает «что считается и откуда взяты данные» — два основных продуктовых факта Pillar B сразу (messaging.md row 9: «Главный proof point Pillar B в развёрнутом explainer-режиме»). Текущий H2 «Edge ratio из реальных свечей» использует слово «реальных» — стилистический усилитель-паразит (Rule 2 / anti-vocabulary §Эмоциональные усилители). Новая формулировка обнажена: имена метрик + источник данных. Edge Ratio переходит в глоссарий ниже (он производное, не основное). R4 — одно предложение, одна запятая, одна точка (точка-с-запятой через em-dash). R5 не задеваем (MAE / MFE — неочевидное, разворачиваются ниже по R6).

### Inline glossary — 3 lines

> **MAE** — Maximum Adverse Excursion: насколько глубоко цена уходила против сделки внутри её жизни.
>
> **MFE** — Maximum Favorable Excursion: насколько далеко цена уходила в вашу сторону.
>
> **Edge Ratio** — средний MFE / средний MAE. > 1 — у системы есть edge; < 1 — система берёт убыток на хвостах.

Rationale: формулировки взяты verbatim из `.agents/product-marketing.md` §Glossary (MAE/MFE) + §Differentiation (Edge Ratio как «производное от MAE/MFE») и из voice.md §Tone calibration #3 (educational explainer — эталонная развёрнутая формулировка). Это inline-словарик в Rule 6-формате: имя метрики жирным, расшифровка аббревиатуры — затем суть в одной строке. Edge Ratio — третья строка, потому что (а) она производная от MAE/MFE и читается только после них; (б) в H2 её больше нет (мы её убрали), значит первый значимый contact = глоссарий, и тут она имеет право на explainer с числовым ориентиром (> 1 / < 1). R5: «цена», «сделка», «стоп», «тейк» не объясняем. R6: для MAE / MFE / Edge Ratio даны конкретные ориентиры и интерпретация. R2: цифры > 1 и < 1 обнажены — без «всего», «целых». R8: «против сделки», «в вашу сторону» — безличное и 2-е pl. Anti-vocabulary scan: clean.

### Body — что MAE / MFE говорят о стопах

> Считаются по минутным свечам MOEX ISS — биржевым, не из реквоутов брокера. Брокерские реквоуты сглаживают экстремумы, биржевые свечи — нет. Средний MAE убыточных в 1,5× дальше стопа — стоп ставится слишком далеко. Средний MFE прибыльных в 2× дальше тейка — тейк закрывается рано. Цифра не спорит.

Rationale: пять коротких утверждений, ни одного придаточного (R4 — 5 точек, 1 запятая в первом, 1 в третьем, 1 в четвёртом; точек больше, чем запятых). Структура: где данные → почему важна биржевая природа данных → один MAE-инсайт → один MFE-инсайт → ритм-якорь «цифра не спорит». Конкретные числа 1,5× и 2× — из `.agents/product-marketing.md` §Problems («средний MAE убыточных сделок в ~1,5× дальше стопа») и из voice.md §Tone calibration #3 (тот же эталон с теми же числами). Это не выдумка — это validated heuristic из материалов продукта. «Цифра не спорит» — повтор фирменной формулы из SimpleFact (favorite vocabulary), создаёт сквозной голос с §4 без явной перекрёстной ссылки. R5: стоп / тейк / убыточные / прибыльные — не объясняем (известное). R6: MAE / MFE уже развёрнуты в глоссарии выше — здесь продолжаем разворот в применении. Anti-vocabulary scan: clean.

### Competitor line

> В России такой автомат — только у нас; у TradeZella и Edgewonk биржи другие, российских свечей нет.

Rationale: симметрично §01 competitor-line, ровно та же формула («только у нас» вместо «ни у кого»). Это **главный** product-defensible differentiator (`.agents/product-marketing.md` §Differentiation #1: «MAE/MFE автоматически из свечей MOEX ISS. В России такой автомат не делает никто. Главный продуктовый дифференциатор, защищённый дольше прочих»). Симметрия §01 / §02 — намеренная: две соседние секции с одинаковой паттерн-formula competitor-line читаются как единая editorial-привычка, не как повтор. Меняется только объект защиты — там Replay, тут автомат.

### Link

**Recommended:** `Подробнее о методе →` *(keep)*

Rationale: «о методе» — точнее, чем «о MAE/MFE», потому что под фичей лежит метод расчёта (минутные свечи ISS + FIFO-привязка партий). Текущая формулировка читается как ссылка на технический раздел документации, что и подтверждается route /manual#mae-mfe. Альтернатива «Как считается MAE/MFE» — допустима, если хотим зеркалить «Как устроен разбор» из §04; но «о методе» — короче и менее вопросительно.

### Rationale

Это **главная** product-defensible секция лендинга после Hero (`.agents/product-marketing.md` §Differentiation помещает MAE/MFE из свечей MOEX на #1 место в списке защищённых дифференциаторов). Поэтому переписан целиком: убран эпитет «реальных» в H2 (anti-vocabulary), добавлен inline-словарик в Rule 6-формате (cro-audit issue #8: «жаргон без explainer» — закрыто), добавлены конкретные числа 1,5× / 2× для практического insight'а, competitor-line сжата до одной строки. Lead pillar — B без дележа (messaging.md row 9 явно: «C здесь как мелкая пометка, но не лидирует»). Voice mix: Sage-ведущий (учительский регистр), Mentor-нотка через «цифра не спорит». Pillar C проходит мелко через «в России» в competitor-line и через «MOEX ISS» в body — но не претендует на основное место.

### H2

Rationale: текущий H2 «Второй взгляд на каждую сделку» работает на эмоциональном уровне, но не даёт продуктового факта. R4: 6 слов, 0 запятых, 1 точка. R8: безличное. Anti-vocabulary scan: clean. R3: «правила против ошибок» — спортивно-ремесленная связка, не ИТ.

### Body

> После каждого закрытия 12 правил проверяют сделку: FOMO-вход, ранний выход без достижения тейка, нарушение размера позиции, торговля против сетапа. Правила детерминированные — описаны в документации, можно прочитать и оспорить. Без чёрного ящика. Без обучения на ваших сделках.

Rationale: переплавлены два текущих параграфа в один — короче, плотнее. Структура: что происходит (12 правил после закрытия) → четыре примера ошибок (FOMO, ранний выход, размер, против сетапа — все verbatim из `.agents/product-marketing.md` Product Overview) → ключевая позиция продукта (детерминированность + читаемость + оспаривабельность) → два отрицания (Sage-формат: «без чёрного ящика, без обучения на ваших сделках»). Главное переключение vs текущей копии: «Никакой магии глубокого обучения» переплавлено в нейтральное «Без чёрного ящика. Без обучения на ваших сделках.» — снимает оборонительный регистр (мы не оправдываемся перед AI-конкурентами), вводит конкретное обещание (ваши данные не идут в обучающий набор — это privacy-claim, не product-claim). R5: FOMO, тейк, сетап — известное, не объясняем. R6: «правила детерминированные» — короткий explainer, потому что концепция определяет фрейм всей секции (messaging.md row 12: «правила, которые можно прочитать в документации и оспорить — defensive positioning против всего рынка AI-trading»). Anti-vocabulary scan: «магия», «глубокого обучения», «ML», «нейросеть» — удалены. Favorite vocabulary: «правила», «сделка», «разбор» — в наличии. Жертвую формулировкой «ты можешь прочитать и оспорить» из текущего текста: «ты» в product-truth-секции запрещено (R8); делаем «можно прочитать и оспорить» — безличное. Это требование задачи: «ты НЕ allowed here».

## Cross-section consistency notes

1. **Competitor-line формула одна и та же в §01 и §02:** «В России такой [фича] — только у нас; у TradeZella и Edgewonk биржи другие, российских свечей нет.» Это намеренный editorial-паттерн (см. §01 Rationale). Если редактор позже захочет варьировать вторую часть («биржи другие, российских свечей нет» → «работают на западных биржах, MOEX-свечей не подтягивают»), допустимо — но обе строки должны изменяться синхронно, чтобы сохранить symmetry.

2. **«Цифра не спорит» — повтор из SimpleFact (§4) в MAE/MFE-body (§9).** Это намеренная sticky-фраза из favorite vocabulary, удерживающая сквозной голос между manifest-секцией и product-truth-секцией. Не маркировать как self-plagiarism — это якорь.

3. **Em-dash vs middle dot в бейдже §04:** Badge «AI-разбор · скоро» использует middle dot, тогда как eyebrow «Раздел 04 — Эвристический разбор» использует em-dash. Это сознательная типографическая дифференциация: em-dash для editorial-конструкций «раздел N — название» (нумерация + название); middle dot для inline-separator коротких label'ов (badge, eyebrow tagger типа «── Журнал сделок · MOEX»). Разделители работают в разных регистрах, не противоречат друг другу.

4. **Inline glossary в §02 — суггестия для implementer:** Три строки глоссария формально не «text body», а semi-tabular content. Предлагаю CSS-класс `editorial-glossary` (или переиспользовать существующий `editorial-table`-стиль с лёгкой адаптацией):
   - **Term** (MAE / MFE / Edge Ratio): JetBrains Mono 13pt caps-or-bold, ink-1 (или ink-2 для контраста с body).
   - **Definition**: Fraunces (или Georgia fallback) 15-16pt, ink-2, italic для расшифровки аббревиатуры в формате `Maximum Adverse Excursion`, затем roman для содержательной части после `:`.
   - **Ритм:** три строки stacked с межстрочным расстоянием ≈ 1.6, разделены тонкой линейкой `border-bottom: 1px solid var(--rule)` (как в editorial-table) либо просто вертикальным space ≈ 24px.
   - Альтернатива: визуально решить как **definition list** через `<dl>` / `<dt>` / `<dd>` — это семантически точнее (term + definition), и accessibility лучше для screen-reader. CSS-класс `editorial-glossary` тогда применяется к `<dl>`, `dt` получает Mono-caps, `dd` — Fraunces-roman.
   - Это input для frontend-design / implementer, не директива копирайтера; финальное оформление принимает дизайнер с учётом существующих токенов cream-palette + Fraunces.
