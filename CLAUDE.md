# CLAUDE.md — Empirik (репозиторий ATOM, папка polistata)

Правила проекта; общие — в `~/.claude/CLAUDE.md`. Даты, причины и решения владельца — `.business/история/решения-по-правилам.md`.

## Проект и пользователь
- **Empirik** — SaaS-журнал сделок для активных ритейл-трейдеров MOEX. Стек: FastAPI + SQLAlchemy 2.0 + Alembic + PostgreSQL (SQLite в dev) | Next.js 16 + React 19 + Tailwind v4 + Recharts | docker compose + nginx. Прежние имена — ATOM, Eqio.
- Вход в базу знаний — `.business/index.md` (карта доменов и триггеры на чтение); профильный `CLAUDE.md` домена — до кода или плана. Правила по коду — `.claude/rules/backend.md` и `frontend.md`, скиллы репо — `.claude/skills/`.
- **152-ФЗ — обязательная остановка:** правка, касающаяся ПДн (регистрация, профиль, удаление, экспорт, логи), начинается с `.business/compliance/152-fz-status.md`. **P&L** — с [ADR-0007](.business/tech/decisions/0007-pnl-methodology-invariants.md).
- Отвечай по-русски. Планка — лучший в мире продукт в своём классе: оригинальнее, удобнее, стильнее; как она проверяется — ниже.
- Env-файлы (`.env`, `.env.local`, `.env.production`) — в `.gitignore`; их содержимое в чат, коммиты и артефакты не выводится.

## Планка мирового уровня
- Класс элемента ДО работы: (1) возможность, которую трейдер сравнивает с лидерами (журнал, дашборд, MAE/MFE, реплей сделки, импорт от брокера, аналитика) → бенчмарк против двух и более лидеров из реестра эталонов, по каждой оси число у нас и у эталона; (2) элемент с опубликованной нормой (WCAG 2.2, 152-ФЗ, локаль ru, контракт API брокера или MOEX ISS) → порог плюс прогон инструмента; (3) внутренность → канон стека. Элемент внутри возможности наследует её вердикт.
- Имена лидеров в правилах не печатаются: их даёт реестр записью с датой, источником и основанием выбора. Записи нет, она просрочена, категория новая или спека заявляет «мы лучше X» → свежий ресёрч и запись в реестр; просроченная запись паритет не подтверждает.
- Реестр эталонов: `.business/эталоны` — эту строку читает `hooks/session_selftest.py`, детектор просроченных записей; формат записи и обновление — `index.md` реестра.
- Вердикт по оси: «`<ось>`: мы `<число+ед.>` vs `<эталон: число+ед.>`, измерено `<чем>`, источник `<URL, дата>`». ПРЕВОСХОДИМ — ось названа до реализации, наше число внешним инструментом, эталон со ссылкой и датой, для метрик три и более прогона с непересекающимися диапазонами, утверждает не автор. ПАРИТЕТ — закрытые возможности эталона плюс явные не-цели. ОТСТАЁМ — «догнать к <дата>» либо «принято, причина». Нет данных — «не опубликовано (URL, дата проверки)». Факты о конкурентах — со страниц продуктов и из документации.

## Порядок работы
- Инструмент → изучи → спланируй → сделай → зафиксируй; план утверждает владелец. Тривиальное (опечатка, переименование, задача в одну фразу) — сразу. Перед работой класса А — интервью: 3–7 неочевидных вопросов про UI, крайние случаи и ограничения.
- Реестр процедур: `.business/Процессы` — эту строку читает `hooks/session_selftest.py`, детектор просроченных и недатированных процедур. Процедура положена операциям: сборка и тесты, docker-стенд, миграция и откат БД, деплой (`.github/workflows/cd.yml`), бэкап Postgres, сверка счёта брокера, заведение правила. Формат и сроки — `index.md` реестра.
- Перед расследованием ошибки — grep по `docs/ERROR_CATALOG.md`; эксплуатация и откат — `docs/RUNBOOK.md`.
- Неясная постановка → `AskUserQuestion`, не угадывай. Незнакомый файл или ветка может быть незавершённой работой владельца — сначала спроси; чужую правку из `git status` не коммить.
- Перед «готово» — объективная проверка: тесты, линтер, `tsc`, сборка, скриншот; критерии по типу правки — путевые правила backend и frontend. Причина, не симптом; правишь одно место третий раз — остановись и предложи переформулировку.
- Не рассуждай о файле, который не открыл; не уверен — «не знаю». Говори конкретно: файл, строка, ожидаемый результат.
- Дефект, который увидел пользователь или прод, — строка в `.business/история/дефекты-у-пользователя.md`: пропустивший слой и артефакт, добавленный, чтобы поймать такой же (строка без артефакта — открытый долг).

## Класс работы — доменная часть
- Получатели Д2, перечень закрыт: пользователь сервиса (трейдер); регулятор (Роскомнадзор). Растяжка «экран конечного пользователя» = экран трейдера, включая лендинг и письма; «документ во внешнюю инстанцию» = политика обработки ПДн, уведомление РКН, согласия.
- Р2 здесь частый: токены брокера и секреты (`TINKOFF_*`, `SECRET_KEY`); P&L, комиссии, тарифы и платежи — деньги; профиль, сделки и логи трейдера — ПДн.
- Класс В по умолчанию (без спеки и судьи; проверка инструментальная): разовый скрипт-замер; разбор логов и выводов инструментов; выбрасываемый эксперимент; перенос и переименование файлов без правки содержания; правка документации и базы знаний без денежных чисел. Поднимает до Б или А: экран трейдера; расчёт P&L или цены; ПДн; любая растяжка. Новая строка перечня — решение владельца.
- Спека — `.business/спеки/<дата>-<задача>.md` по `.business/_шаблоны/Спека.md`; долг PASS-with-debt и прогресс — `.business/история/в-работе/<задача>.md`. Механика — путевые правила `.claude/rules/спеки.md` и `.claude/rules/история.md`. Старые спеки в `docs/superpowers/specs/` — история, новые туда не пишутся.

## Параллельные агенты и git
- В дереве может работать второй агент: файлы в индекс только поимённо; `git reset` и `--amend` — нет, пока он работает; push сверяет `~/.claude/hooks/guard_push_provenance.py`.
- Изоляция агентов — рабочее дерево: `git worktree add ../.worktrees/<трек> -b feat/<трек>`.
- Хуки репо включаются после клона: `git config core.hooksPath .githooks` (gitleaks, линтеры спек и прогресса, pre-push гейта).

## Между сессиями
- Начало: реестр живых треков `.business/история/в-работе/index.md` — впиши себя в «Активные» до первого действия (правило H), файл прогресса, реестр процедур, последние коммиты — потом действие. Конец: рефлексия `.business/история/YYYY-MM-DD-<название>.md`. Ценное кросс-сессионное — auto-memory, не дублируя рефлексию.
